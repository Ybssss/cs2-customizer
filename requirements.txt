# CS2 Customizer - core runtime dependencies (NOT the Qt-specific ones)
#
# WHY THIS FILE EXISTS
#   requirements_qt.txt is Qt-only, and its own comments say the core runtime
#   dependencies live in "requirements.txt". The open-sourcing did not carry that
#   file, so installing requirements_qt.txt alone could not produce a working
#   program. It failed twice, silently:
#     1. following the README then `python main_widget.py` -> ModuleNotFoundError:
#        flask. gsi_server.py:7 is a TOP-LEVEL import and the GSI receiver is
#        started by the main window, so the program cannot start at all.
#     2. the first published Release (v2.3.1) shipped an installer that died on
#        "No module named 'flask'" - the packaging job installed the Qt half only.
#   Full account: PROGRESS.md, entry 10.
#
# WHY THE COMMENTS HERE ARE ASCII
#   pip decodes a requirements file with the MACHINE'S LOCALE CODEC, not UTF-8.
#   On a Chinese Windows box (this project's primary audience) that is GBK, and
#   UTF-8 Chinese in the comments is not always decodable: pip 23.2.1 raised
#   UnicodeDecodeError reading this file before it even started resolving. A
#   requirements file is read by pip on arbitrary machines, so its comments must
#   stay ASCII. The narrative version lives in PROGRESS.md.
#
# WHY requirements-ci.txt NO LONGER REPEATS THIS LIST
#   It used to list every package below a second time. Two copies of one list is
#   how "CI installs it, packaging does not" happens: CI stayed green while the
#   artifact stayed broken. Now this file is the only copy and requirements-ci.txt
#   references it.
#
# Every version bound below is identical to what requirements-ci.txt had before.
